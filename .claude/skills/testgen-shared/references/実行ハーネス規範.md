# 実行ハーネス規範

## 前提条件

本キットは **Spring Boot アプリケーション+Testcontainers+Playwright for Java+JUnit** を
前提とする。スキーマ管理は migration 機構(既定 Flyway)を前提とする。前提を満たさない
プロジェクトでは、キットの転写・実行を試みず停止してユーザーに確認する。

アプリ固有の接合(起動・コンテナ設定クラス、ログフィルタの対象パッケージ等)は、キットに
書かず、exec が転写時に生成する**糊クラス**が供給する(キットは中立パッケージを維持する)。

## 実行

- **プロファイル**: 既定 `e2e`(`application-e2e.yml`)。`test`(Testcontainers が
  `@ServiceConnection` でデータソース上書き)を踏襲し、実ログイン/認可を通し、ベースライン
  投入を有効化する。
- **アプリ起動**: 自動 E2E は `@SpringBootTest(webEnvironment = RANDOM_PORT)`+Testcontainers
  で同一プロセス起動。DB のリセット/シードはテストが同一プロセスで行う。手動確認/MCP
  オーサリング用の起動クラスを `src/test` に置く。
- **コンテナ**: ローカルは reusable container+実行前リセット、CI は実行ごとに新品。
- **スキーマ/データ**: スキーマは migration 機構(既定 Flyway)。データはベースライン seeder
  が正本 csv を読み込んで投入する。ベースラインはマスタ/参照系のみ。
- **冪等性**: 実行前にアプリ表を `TRUNCATE ... RESTART IDENTITY CASCADE` してベースラインを
  再投入する。更新系シナリオは自己完結とする。
- **メール**: 送信を伴う画面が受け入れ対象のときのみ偽 SMTP(MailHog)で受信検証する
  (受信箱 Web UI を開いて映す)。
- **検証部品**: テストの検証・操作フレームは **`E2eVerify` 部品経由のみ**とする。素の
  Playwright アサーション・JUnit アサーション・DOM 読取の直呼びは禁止し、**ArchUnit が
  構造的に強制**する(通常 `test` タスクで実行。テストクラスは DOM 読取全面禁止、
  Page Object・糊クラス等のキット外は `@E2eRawDom` 付きメソッドに限り生 DOM アクセス可。
  付与条件は testgen-exec スキル)。仮想化グリッドの検証は**グリッドアダプタ**
  (`E2eGridAdapter`。ag-grid 実装はキット同梱、他ライブラリはプロジェクト側で実装)を
  部品へ渡して行う。**列幅の変更・最小幅への到達もアダプタの操作 API で行い、テスト側で
  リサイズドラッグを手組みしない**(ドラッグの解釈はライブラリ内部仕様に依存し、手組みは
  非決定な結果を生む)。部品カタログは testgen-exec スキルを参照。
- **設定値の検証**: タイムアウト長・有効期限など「時間・上限の設定値そのもの」が仕様である事項は、
  実行中アプリの有効設定値を検証部品(`E2eVerify.sessionTimeoutIs` 等)で機械検証する
  (実時間待ちは用いない。到達手段カタログ 手段6)。**検証対象の設定は `application-e2e.yml` で
  上書きしない**(上書きすると機械検証が E2E 用の値を見るだけになり無効化されるため)。
- **障害シーム**: サーバー内部の異常分岐(ロールバック・内部エラー・送信失敗・競合検出等)は、
  テストプロファイル限定の**委譲シーム Bean**(機能対応物として exec が作る)で再現する。
  状態管理(ケース単位トグル・発火後自動解除・ベースラインリセット時に全解除)と発火の機械記録は
  キットの `E2eFaultSeams` が担う。到達手段の使い分けは「到達手段カタログ」を正本とする。
- **操作ディレイ**: 通常の `e2eTest` は slowMo=0。受け入れ用証跡は **`e2eEvidence` タスク**
  (slowMo 既定 500ms)で生成する。
- **受け入れ用ビューアの生成**: `e2eEvidence` の後段タスク `e2eEvidenceIndex` が生成する
  (testgen-exec スキル同梱ツール。要 Python+`openpyxl`。仕様ルート等はビルドスクリプトが
  引数で渡す)。対象はテスト実行と同じ指定から決まる。証跡はそのままでビューアだけ作り直す
  ときは、同じ指定で `e2eEvidenceIndex` を単体実行する。生成失敗はビルドを失敗させる
  (`openpyxl` 未導入のみ警告)。

## ツール

- **E2E**: Playwright for Java。成果物は `src/test` 配下の E2Eテスト(JUnit+Page Object+
  検証部品)。既定 `test` は `e2e` タグを除外し、`e2eTest`/`e2eEvidence` タスクで実行する。
  Playwright MCP はオーサリング/検証の手段であり成果物ではない。
- **ドキュメント変換**: doctool で docx/xlsx 本文を md 化する。
