## 2026-08-31 再実行後の是正（是正H・是正I）

`11_案件情報一覧` の exec 再実行（e2eTest）で残った6失敗（1-3・2-3・2-5・2-9・2-10・4-15）は、
仕様書・テスト実装の誤りではなくキット `gridColumnHeaders` の事前走査の座標計算不具合
（要求スクロール値で位置を計算するため、グリッドのスクロール調停で要求が反映されない場合に
同一列が別位置として重複記録され、実在列が重複統合に飲み込まれる）と切り分けた。
キット改修（付随を参照）後、6件の再実行成功を確認済み。本節はこの切り分けの過程で確定した
仕様書側の是正2件を記録する。

### 是正H: 1-5 手順3 を列リサイズの物理機構と整合させる

ag-grid のリサイズハンドルは各列ヘッダーの右端にあり（`.ag-header-cell-resize { right: -3px }`）、
境界線のドラッグは境界の**左側**の列の幅を変える（2-6 の「境界線の左側の『件名』列の幅が広がる」と
同一の機構）。「案件概要」列の左側の境界線をドラッグすると左隣「商流」列が変わり、案件概要は
初期幅350pxのままとなるため、期待する結果（案件概要の切り詰め）へ到達できない。

| 対象 | 変更 |
| --- | --- |
| `11_案件情報一覧` 1-5 | 手順3「『案件概要』列の**左側**の境界線をドラッグして〜」→「『案件概要』列の**右側**の境界線（『開始日』列との間）をドラッグして列幅を最小（80px）まで狭める」（観点・期待する結果は不変） |

### 是正I: 2-6 幅増加の機械検証を仕様書へ宣言（是正G 2-6 行の実現手段・これで決着）

是正G の「『幅が広がる』を幅実測の機械検証で追加」は仕様書に【機械検証】宣言が無く、規範
（machineEquals は仕様書で【機械検証】と宣言された期待結果に限る・1:1）の下では実装経路が

（既定幅 220px + 100px = 320px）。
