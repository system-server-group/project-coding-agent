# 証跡規範

受け入れの主体は**コマ送り静止画（フレーム）＋steps.json**である。動画・トレースは補助であり、**合否判定の根拠はステップフレームと steps.json に限る**。

1. **1操作・1検証＝1フレーム**。操作は結果が現れる要素を、検証は検証対象を、フレーム内へ完全に映す（**見切れ禁止**。ハーネスが機械検査し、収まらなければ失敗する）。複合操作は観測可能な変化ごとに分割する。**画面遷移・画面の作り替えを起こす押下操作は、押下前（操作対象を青枠で明示）・押下後（結果）の2フレーム**で記録し、どの要素を押したか＝操作の再現性を証跡に残す。
2. **ハイライト**: 検証対象は赤枠＋番号バッジ、操作対象は青枠で示す。
3. **状態遷移（表示↔非表示・消去）は前後フレーム必須**。変化前の状態をフレームに残し、変化後は同じ画角で「消えた領域」を破線ゴースト枠で示す（transition 部品）。単発の非表示検証は認めない。**初期状態の「無いこと」**（遷移を伴わない不在）は、無いことの文脈を示す実在要素（アンカー）を可視検証して**破線枠＋ラベルで図示**し、その文脈で対象が存在しないこと（0件）を機械検証する（absent 部品の規格。図示の無い素通しフレームによる不在の検証は認めない）。
4. **ビューポートより大きい要素**は要素単体ショット（`..a.jpg`）を補助フレームとして添付する。
5. **1フレームに収まらない検証対象**は**スクロール連続フレーム規格**で検証する。**縦（行）**: 連続する各フレームは直前の末尾2行を重複して含み、行キー（ID列）を必ず写し、キャプションに「フレーム n/N・キー範囲」を記録する。末尾フレームの後に**行数の締め**（期待件数の次の行が存在しないこと＝余剰行の不在）を機械検証する。**横（列）**: 連続する各フレームは直前の末尾1列以上を重複して含み、フレーム内で完全に見えている列すべてを期待順と突合してハイライトし、キャプションに「フレーム n/N・列範囲」を記録する（**列の順序確認に固有の採番規格**: ハイライトのバッジ番号は固定列を含む全列の列順の番号であり、フィルム全体を通して 1→N へ一度だけ進む——固定列 1..P は**最初のフレームでのみ**番号を付け、以降は枠のみで示す。隣接フレームの重複列は同一番号で両フレームに現れ、継ぎ目の連続性を示す。固定列は毎フレーム検証する。列幅が窓を超える列は単独フレーム＋要素単体ショットで見切れを明示する）。仮想化グリッド（画面外の行・列が DOM に存在しない）に限らず、通常のテーブル・リストのスクロールが本質のケース（到達手段カタログ 手段7）にも適用する。
6. **ネイティブUI（datalist候補・confirmダイアログ・ファイル選択等）と DLファイル内容**は録画・撮影に写らないため、DOM 内容・DL実物を描画した**代理証跡**（ラベル必須）＋機械検証で扱う。項目が多い場合の代理証跡は**スキャン対象の明示＋先頭サンプル（10件程度）の可視化＋全件の機械突合（期待値正本参照）**で構成し、全件のフレーム化は行わない。ヘッドレス実行ではネイティブUIが偶発的に写り込むことがあるが、**環境依存の描画のため判定根拠にしない**（代理証跡が正）。操作の結果出力されたファイルは**DL実物を証跡として保存**し、ビューアから開けるようにする。
7. **画面に出ない検証**（属性・HTTP応答・API不呼出・不送信の否定観測等）は、仕様書の期待結果に**【機械検証】**と明記し、期待値・実測値を steps.json に記録する（隠さず、監査可能にする）。**効果が後続フレームで可視にならない合成操作**（セッションCookie削除等のブラウザ状態の直接操作）は、操作直後にその**効果の実測を【機械検証】として記録**する。機械検証を用いてよいのは仕様書で【機械検証】と宣言された期待結果に限り、**可視で確認できる期待結果を機械検証で代替してはならない**（検証部品が連続フレーム規格等の一部として内部的に記録する機械ステップはこの限りではない）。
8. **証跡ログ**: 画面遷移（NAV）・操作・検証の期待/実測、アプリログ（自パッケージ全レベル＋他 WARN 以上）、ブラウザコンソール（自アプリ画面の warning/error のみ）を時系列で steps.json に記録し、ビューアのコンソール欄に表示する。リダイレクト等、見た目で確認しにくい事実の補強に用いる。証跡ログは**時系列（ts）順に整列**して記録する（記録経路による順序差を許さない）。
9. **全体撮影（ビューポート拡大の全高スクリーンショット）は行わない**（廃止。仮想化行が写らない等の理由で判定根拠になり得ないため）。
10. 各ステップは時刻（`ts`）を持ち、証跡ログと突き合わせできる。
11. **キャプション（desc）はアサーションと一致させる**: 各ステップの desc が主張してよいのは、そのステップのアサーション（機械検証を含む）が実際に検証している事実だけ。アサーションが検証しない事柄（周辺の表示・別要素の状態・範囲の網羅）をキャプションの文言で主張してはならない。
12. **CSS描画にのみ現れる視覚表現**（テキストの省略表示・強調の配色・罫線の有無等）は、DOM の文字列・属性の機械検証で代替できないため、これらに対する【機械検証】を導出しない。可視検証（スクリーンショット証跡の目視）で扱い、期待結果は見た目の趣旨（例:「文章が続いていることを示す省略表現が付く」）で表現する。DOM に現れる状態（クラス付与等）が仕様に定められている場合に限り、その状態の機械検証を併用してよい。
