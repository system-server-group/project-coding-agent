# 入力値チェックの実装規範

> 共通規範は [00_実装共通規範.md](00_実装共通規範.md) を参照。
> チェック内容・文言の正本は基本設計のシステム共通仕様書（入力値チェック）。

## 配置
- **システム共通仕様の汎用チェック**（単項目：使用文字・日付値域・最大文字数 等）は共有の
  `com.system_server.ai_demo.commons.validation` に置く（制約注釈＋ Validator）。機能ごとに重複実装・機能パッケージに閉じ込めない。
  - 標準制約で表せるものは標準を使う（例：最大文字数＝`@Size`）。
- **クロス項目チェック**（例：日付下限＝至が自以降）も、比較対象の**プロパティ名・ラベルを注釈属性で外出し**すれば汎用化できる。
  検証本体は `commons/validation` に置き（対象オブジェクトからプロパティ名で値を取得して比較）、**項目名・ラベルは使用側 DTO の注釈で宣言**する。機能ごとの検証クラスを作らない。

## メッセージ
- 共通仕様の文言は `commons.validation.CheckMessages` に**一元化**し、各所にべた書きしない。
  - 例：`@Size(max = N, message = CheckMessages.MAX_LENGTH)`（`{max}` は Bean Validation が制約属性から補間）。
  - 文言は Java 定数（UTF-8 ソース）で保持し、`ValidationMessages.properties` のエンコーディング依存を避ける。

## 参考（配置・実装の例示）
> 本節は配置・実装パターンの例示であり、現存実装の一覧ではない。物理名・有無は各設計書（正本）に従う。

- `commons/validation/`：`AllowedCharacters`・`DateInBounds`・`DateRange`（＋各 Validator）・`CheckMessages`
- `apps/projects/models/ProjectSearchCondition`：`@DateRange`／`@DateInBounds`／`@Size`／`@AllowedCharacters` を宣言（項目名・ラベルは注釈で外出し）
