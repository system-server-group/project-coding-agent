# 区分（列挙型）の実装規範

> 共通規範は [00_実装共通規範.md](00_実装共通規範.md) を参照。本書は区分（列挙型）の実装固有の事項を記す。
> 設計書（列挙型定義書）の記載規範は **列挙型定義書 記載規範** を参照（言語非依存・定数の定義のみ）。

## 基本方針
区分コードと列挙値の相互変換ロジックを**各列挙型に重複実装しない**。変換は共通部品に一元化する。

## 配置
- 列挙型（区分）は**機能横断のドメイン型**（設計上、型情報は機能グループ＝横断）。機能パッケージに置かず、
  横断パッケージ `com.system_server.ai_demo.enums` に置く。
- 抽象（`CodeEnum`／`CodeEnums`／`CodeEnumSerializer`）は**技術基盤**として `commons.code` に、
  具体の区分定数は `enums` に置いて住み分ける（commons にドメイン定数を入れない）。

## 共通部品
- `com.system_server.ai_demo.commons.code.CodeEnum`
  - DB に区分コードで永続化される列挙型が実装する共通インターフェース。
  - `getCode()`（DB 格納用の区分コード＝定数物理名）／`getLabel()`（画面・CSV 表示用の論理名）を持つ。
- `com.system_server.ai_demo.commons.code.CodeEnums`
  - `fromCode(Class<E>, String)`：コード → 列挙値。未知コードは `IllegalArgumentException`。
  - `fromCodeOrNull(Class<E>, String)`：任意項目向け。`null` は `null` のまま返す。

## 各列挙型の実装ルール
- `CodeEnum` を `implements` する。
- 各定数はコンストラクタで**区分コード（型情報定義書の「定数物理名」の値）とラベル（論理名）**を受け取り、フィールドに保持する。
  - `getCode()` は保持する区分コードを返す。
  - `getLabel()` は保持するラベルを返す。
- 区分コードの取得・永続化・API 入出力・変換は、すべて `getCode()` が返す値で行う。
- **`fromCode` 等の解決メソッドを列挙型に定義しない**（共通部品 `CodeEnums` を使う）。`CodeEnums` は各定数の `getCode()` で突合する。

## 変換の呼び出し（サービス層）
- 必須項目：`CodeEnums.fromCode(Xxx.class, code)`。
- 任意項目（コードが `null` を取りうる）：`CodeEnums.fromCodeOrNull(Xxx.class, code)`。
- 列挙型ごとの `null` 判定ラッパーをサービスに置かない（`fromCodeOrNull` に集約）。

## JSON 出力（API）
- 区分は API レスポンスで **`{ "code": ..., "label": ... }`** の形で返す。共通シリアライザ
  `com.system_server.ai_demo.commons.code.CodeEnumSerializer`（`CodeEnum` 用、`org.springframework.boot.jackson.JacksonComponent` で登録）が一括で担う。
  - 目的：画面側でコード→ラベルの対応表を重複定義させない（表示は `label`、判定は `code`）。
  - 各列挙型・DTO に個別のシリアライズ注釈を付けない。
  - デシリアライズ（入力）は既定どおり**コード文字列**で行う（本シリアライザの対象外）。

## 参考（配置・実装の例示）
> 本節は配置・実装パターンの例示であり、現存実装の一覧ではない。物理名・有無は各設計書（正本）に従う。

- 横断ドメイン区分は `enums/` 配下（例：`Status`・`BpRecruitment`・`ContractType`。物理名は型情報定義書が正本）
- 区分コード→列挙型の変換呼び出しはサービス層（例：`apps/<機能>/services/*Service`）
- JSON 出力は `commons/code/CodeEnumSerializer`
