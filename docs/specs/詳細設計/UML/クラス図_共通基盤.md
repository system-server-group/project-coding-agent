# クラス図 ― 共通基盤（認証・認可／共通レイアウト／エラー／ログイン）

論理名で表記（物理名は各定義書で確定）。レイヤ: コントローラー → サービス → Mapper(1表専用) → エンティティ。
認証・認可はフレームワーク（フォームログイン／URLベースのアクセス制御）が担うため、本図には業務クラスとして示さない（許可表・アクセス制御の遷移は画面遷移図を参照）。共通レイアウトはコントローラー定義を持たず（コントローラー一覧表に定義なし）、画面テンプレート一覧の「共通レイアウト」と画面イベント「初期表示」（共通レイアウト_初期表示_画面イベント定義書）として定義される。その初期表示はユーザ参照・部署参照（マスタ管理所属の横断参照）を利用する。

```mermaid
classDiagram
    direction LR

    class ログイン画面コントローラー {
        <<controller>>
        +ログイン画面表示()
        +認証要求(ユーザID, パスワード)
    }
    class 共通レイアウト {
        <<template>>
        +初期表示()
    }
    class エラー画面コントローラー {
        <<controller>>
        +エラー振り分け(404/403/500)
    }
    class ユーザマスタマッパー {
        <<mapper>>
    }
    class 部署マスタマッパー {
        <<mapper>>
    }
    class ユーザマスタレコード {
        <<entity>>
    }
    class 部署マスタレコード {
        <<entity>>
    }
    class ユーザ参照サービス {
        <<service>>
        +ユーザ名一覧取得()
        +ユーザ名取得()
        +部署ID取得()
    }
    class 部署参照サービス {
        <<service>>
        +部署名取得()
        +部署存在判定()
        +部署名一覧取得()
    }

    共通レイアウト --> ユーザ参照サービス
    共通レイアウト --> 部署参照サービス
    ユーザマスタマッパー --> ユーザマスタレコード
    部署マスタマッパー --> 部署マスタレコード
    ユーザ参照サービス --> ユーザマスタマッパー
    部署参照サービス --> 部署マスタマッパー
```

> 補足: 認証・認可はフレームワークのフォームログイン・URLベースのアクセス制御が担い、許可表・アクセス制御の遷移は画面遷移図を参照する（本図では業務クラスのみを示す）。ユーザ参照・部署参照は機能グループ＝マスタ管理に所属する横断参照リソースだが、テーブル/DBIF のみに依存するため共通基盤からも利用される。
