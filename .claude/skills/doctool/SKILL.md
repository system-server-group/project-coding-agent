# いつ使うか

- 既存の設計書の内容を確認するとき。
- 設計書の雛形や凡例をテンプレートにして設計書を作成・更新するとき。
- 平坦なテキスト抽出では失われる構造(入れ子表・結合セル・テキストボックス・自動採番・フィールド・方眼紙レイアウト・図形の遷移グラフ)を保ったまま読み書きしたいとき。

## 前提・注意

- コマンドはリポジトリルートで実行する。
- `{{doctool}}` は doctool スクリプトの配置ディレクトリ。本スキルに同梱されており、スキルディレクトリからの相対パス `scripts/doctool` で解決する。
- Windows ネイティブ Python は標準出力が既定で cp932 のため、文字化け防止に `PYTHONUTF8=1` を付ける。
- docx の読み取り(`dump` / `preview` / `cache` / `analyze`)は Python 標準ライブラリのみで動作する。
  生成(`fill`)は docx=`python-docx` / xlsx=`lxml`、xlsx の読み取りは `openpyxl` が必要。
  `fill` は**出力(`output`)の拡張子**で docx / xlsx のライターを振り分ける。

## 1. 読み取り(内容の確認)

```
# 構造化 JSON(IR)。生成スペックの座標はこの IR と同じアドレス体系
PYTHONUTF8=1 python {{doctool}}/doctool.py dump <file>

# Markdown プレビューを標準出力へ出し、同時に .doctool-cache/ へ保存する
PYTHONUTF8=1 python {{doctool}}/doctool.py preview <file>

# コンテキスト節約のため、Markdown を標準出力へ出さず .doctool-cache/ へ保存する
PYTHONUTF8=1 python {{doctool}}/doctool.py cache <file> [...]

# ファイル実体の sha256 指紋(型不問)。設計変更検出の lock(ベースライン)記録に使う
PYTHONUTF8=1 python {{doctool}}/doctool.py hash <file> [...]

# lock 記録の指紋を現在の実体と突合。changed/missing があれば終了コード1(*gen の変更検出ゲート用)
PYTHONUTF8=1 python {{doctool}}/doctool.py status --lock <lock.json> [...]
```

`preview` では従来の平坦なテキスト抽出では失われていた構造が可視化される:
結合セル(`<`=左に結合 / `^`=上に結合)、自動採番欄(`(自動採番)`)、
フィールド(`⟨PAGE⟩` 等)、入れ子表(`《入れ子表n》`)、テキストボックス。

`preview` / `cache` は、読み取った Markdown をリポジトリルート直下の
`.doctool-cache/` に保存する。`.doctool-cache/` は doctool が読み取った
全ドキュメント共通の派生キャッシュであり、特定のスキルや文書種別に専有させない。
配置はプロジェクトルートからの相対パスを維持し、元拡張子を残した `.md` とする。

- 入力: `<relative/path>/<file>.xlsx`
- 出力: `.doctool-cache/<relative/path>/<file>.xlsx.md`

`preview` / `cache` は元ファイルの sha256 指紋をキャッシュ先頭のメタコメント
(`<!-- doctool-cache source-sha256=... -->`)に埋め込み、**元ファイルが未変更なら
再生成をスキップ**する(コストの高い読み取り自体を省く)。この判定により、透過的に
キャッシュ経由で Markdown を読める。`cache` は最新なら `up-to-date:`、再生成時は
`cached:` を表示する。`preview` は最新ならキャッシュ本文をそのまま標準出力へ返す。
指紋に関わらず作り直したいときは `--force` を付ける。

一時的に標準出力だけ確認したい場合は `preview --no-cache <file>` を使う(キャッシュを
読まず書かず常に再生成)。
リポジトリルート以外から実行する必要がある場合は `--project-root <root>` を指定する。

**自動採番の検出は、段落の直接 `numPr` に加え、段落スタイル由来(`basedOn` 連鎖・
`numStyleLink` 含む)も解決する**。`dump` の `numbering` には `numId`/`level` に加え
`source`("direct"|"style")、`format`(numFmt: "decimal"/"bullet" 等)、`ordered`(連番なら
true)が付く(`numId=0` は採番打ち消しとして採番なし)。連番(ordered)か箇条書き(bullet)かを
区別できるため、書式設定による採番の取りこぼしを防げる。

## 2. 雛形の解析(生成前に必ず実行)

```
PYTHONUTF8=1 python {{doctool}}/doctool.py analyze <file>
```

雛形ごとの記入ストラテジ(自動採番・フィールド・結合・複数段落セルの判定ルール)を機械判定して出力する:
自動採番セル・フィールドセル・結合セル・複数段落セルと、注意書き(`notes`)。
ここで判定できない特殊構造が成果物に関わる場合は、推測せずユーザーに確認する。

## 3. 生成(凡例を雛形に差し替え)

1. `dump` の IR で差し替え対象の座標(part / block / row / col)を特定し、
   `analyze` の注意書きを踏まえて記入スペック(JSON)を作成する。
2. `fill` で生成する。

```
PYTHONUTF8=1 python {{doctool}}/doctool.py fill <spec.json>
```

`fill` は保存前に自動採番を**表ごとに独立採番**へ正規化する。
Word の自動採番は `numId` 単位で連番カウンタを共有するため、表の複製や凡例の
`numId` 共有があると表をまたいで連番が地続きになる。これを各表1始まりに振り直す
（最初に使う表は維持し、2つ目以降の表へ開始値1の新しい `numId` を割当て）。
対象は**連番(ordered)**のみ（箇条書きは除外）。採番が段落の直接 `numPr` でなく
**段落スタイル由来**（heading 等）の場合は、スタイルを書き換えず当該段落へ直接 `numPr`
を被せて表ごとに独立させる（スタイルの書式は保持）。

### 3-1. xlsx の生成(fill)

出力を `.xlsx` にすると xlsx ライターが使われる。ライターは **worksheet / styles / drawing の
XML を直接編集**し、それ以外のパート(charts/media=図形・画像、カスタム XML 等)を
**byte 単位で保持**する(要 lxml)。openpyxl の再保存で落ちる非モデル化パート
(レガシー VML の図形・一部グラフ・ピボット等)も失われず、行の挿入/削除では結合と
**描画アンカーを追従**させる。番地は `ref`(A1 表記。例 `C3`)、結合セルは
worksheet の `mergeCells` から起点(左上)へ解決する。操作(`operations`):

- `setCell`：値を設定(インライン文字列)。`text`(文字列)または `paragraphs`(文字列配列=
  セル内改行)。配列・改行を含む値は `\n` 連結(折り返し表示はセル既存書式の wrapText に依存)。
  値 `null` は据え置き。既存の style 参照(`s`)を保持する。
- `clearCell`：値だけ消す(書式は残す)。
- `setFormat`：`styles.xml` に派生 xf を追記しセルの `s` を差し替える。`format` キーは
  bold/italic/underline/strike・color/sizePt/font・align・fill(=塗り)。Excel はセル単位書式のため
  `find`(セル内部分書式)は不可。
- `replaceText`：セルの**格納文字列**への部分置換(既定は最初の一致、`all:true` で全置換)。
  日付・数値セル(シリアル値)は表示文字列と一致しないため `setCell` を使う。
- `fillTable`：見本行(`templateRow`=Excel 行番号)の書式を複製して `rows` を `startRow`
  (既定=`templateRow`)から書き込む。既定は **overwrite(上書き。行数・結合・描画アンカーは
  変えない=罫線を敷いた固定表領域向け)**。`"insert": true` のときは 1 行目を上書きし残りを
  **挿入**して、挿入位置より下の 行・結合・**描画アンカーを下方向へ追従**させる(行を増やして
  図形を追随させたいとき)。
- `deleteRow`：Excel 行を削除(`row`=Excel 行番号)し、下の 行・結合・描画アンカーを上方向へずらす。
- `setRowHeight`：行高を設定する。`row`(単一)または `rows`(複数)+`heightPt`(固定高。
  `customHeight` を付与。上限 409.5pt)。`"auto": true` は固定を解除して Excel の自動高さに戻す。
- `mergeCells`：セル結合を追加する(`ref`="A10:A12" 形式)。同一の結合が既にあれば何もしない。
  既存結合と部分的に重なる指定はエラー(重複結合はファイル破損の原因になるため)。

**印刷範囲(`_xlnm.Print_Area`)**：記入(`setCell`/`replaceText`/`fillTable`)が既存の印刷範囲を
はみ出す場合、範囲を記入セルまで自動拡張する(既存領域 ∪ 記入セルの外接矩形)。`insert`/`deleteRow`
の行シフトは印刷範囲側の行にも反映する。**印刷範囲が未定義のシートには新規作成しない**(全面印刷を
維持)。`Print_Titles`(見出し行の繰返し)など `Print_Area` 以外の定義名は変更しない。

xlsx には Word の `numId` 共有連番が無いため採番正規化は行わない(「No」列は手打ちリテラルとして
値をそのまま書き込む)。数式セルの参照は行シフト時に書き換えない(テスト仕様書は数式を持たない前提)。
- `replaceText` はセルの**格納文字列**への一致で、日付・数値セル(シリアル値)は一致しないため
  `setCell` を使う。数式セルの参照は行シフト時に書き換えない(テスト仕様書は数式を持たない前提)。

### 3-2. xlsx の行高調整(fitrows)

生成した xlsx のケース行が Excel の行高上限(409.5pt)を超える長文を持つ場合に、
そのケースを複数行に分割(行挿入+縦マージ+明示行高)して全文を表示可能にする。
行高は Excel COM やフォント計算ではなく、**Excel が保存したファイルの実測 `ht`** から取得する。
固定高(`customHeight`)の行は `ht` が内容と無関係な明示値で見切れを検出できないため、
**元の高さを退避したうえでいったん自動高さへ戻し、Excel に実測させる**(round0)。

```
PYTHONUTF8=1 python {{doctool}}/doctool.py fitrows <spec.json> [--check|--auto]
```

spec(JSON)の例:

```json
{
  "file": "docs/tests/.../xx_テスト仕様書.xlsx",
  "anchorColumn": "A",
  "anchorPattern": "^\\d+-\\d+$",
  "columns": "A:I",
  "maxRowPt": 400,
  "slackPt": 3,
  "pageHeightPt": null
}
```

`slackPt`(既定 3)は固定高行を**引き上げるときの上乗せ**。現行の固定高が実測必要高に
足りない行だけを対象にし、`実測 + slackPt` を新しい行高にする(足りている行は変更しない)。

**運用フロー(Excel での保存が測定手段)**:

Windows + デスクトップ版 Excel がある環境では **`--auto` を使う(推奨)**。下記フロー中の
「Excel で開いて保存」を excelsave(COM 自動化。非表示・マクロ無効・ダイアログ抑止)が代行し、
**人手なしで完了まで実行**する。対象ファイルを Excel で開いたままだとエラーになるので閉じておく。
excelsave が失敗した場合(Excel 未インストール等)は下記の手動フローに切り替える。
「開いて保存」だけを単独で行うコマンドもある(`doctool excelsave <file.xlsx>`)。

手動フロー(`--auto` が使えない環境):

1. `fill` で生成した xlsx を **Excel で開いて Ctrl+S で保存**する(自動高さ行に実測 `ht` が記録される)。
2. `fitrows` を実行する(round0)。
   - 固定高(`customHeight`)のケース行があれば、元の高さを退避行としてシート末尾(印刷範囲外)に
     書き込んでから固定を解除し、**終了コード3** で「Excel で開いて保存して再実行」を案内する。
     この状態のファイルを開くと**対象行が既定高に見える**(測定のための一時状態)。
3. もう一度 Excel で開いて保存 → `fitrows` を再実行する(round0b → round1)。
   - 退避行の実測 `ht` を回収し、元の高さで足りる行は**元へ復元**、足りない行は
     `実測 + slackPt` へ引き上げる。実測が頭打ちの行は自動高さのまま次段へ送る。
   - 頭打ち行(`ht`>=409.4)も既存の分割ブロックも無ければ「変更なし」で完了(通常ここまで)。
   - あれば測定用のスクラッチ行(明示改行単位の断片)をシート末尾(印刷範囲外)に書き込み、
     **終了コード3** で「Excel で開いて保存して再実行」を案内する。
4. もう一度 Excel で開いて保存 → `fitrows` を再実行すると、断片実測の合算で必要高を確定し、
   分割・調整を適用してスクラッチを削除する(事後検証込み)。

注意:

- 上限内に収まっている**自動高さ**のケース行には何も**しない**(自動高さのまま維持)。
- 固定高のケース行は毎回 round0 で再測定される。足りていれば元の高さへ戻すだけで、
  **縮小はしない**(意図して持たせた余白は維持される)。
- 分割ブロックの行高は明示設定される(結合セルは Excel の自動調整対象外のため)。同じ理由で、
  **横方向に結合されたセルを含む行では round0 の自動高さ再計算が効かない**。
- 明示改行の無い一続きの文章が単体で上限を超える場合は測定不能としてエラーになる(文章の分割が必要)。
- 1ケースの表示高が印刷1ページの本文高さ(用紙高 - 上下余白 - `Print_Titles`)を超える場合はエラー。
  `pageHeightPt` で上限を明示指定できる。
- **手動フローの手順1の保存忘れは機械検知できない**(「変更なし」と誤判定し得る)。手順2以降の
  保存忘れは退避行・スクラッチ行の `ht` 有無で検知される(終了コード3)。`--auto` は保存を
  doctool 側が行うため、この懸念自体がない。
- round0 で固定を解除した状態のまま中断しても、**退避行が残っている限り次回実行で元の高さへ
  復元される**(実測が無ければ終了コード3 を返して退避を維持する)。
- `--auto` と `--check` は併用できない(`--auto` は測定のために Excel 保存でファイルを更新する)。
- 既存の分割ブロックは実行のたびに再測定され、不足していれば行の追加・高さ引き上げで是正される
  (意図的な余裕は維持。縮小はしない)。

## 4. 既存ファイルの採番正規化

手動編集等で既存 docx に「表をまたいだ連番継続（地続き）」が残っている場合に是正する
（`fill` と同じ正規化を既存ファイルへ適用し、変更時のみ上書き。冪等）。

```
PYTHONUTF8=1 python {{doctool}}/doctool.py normalize <file.docx> [...]
```
