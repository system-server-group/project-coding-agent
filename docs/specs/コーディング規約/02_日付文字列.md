# 日付の実装規範

> 共通規範は [00_実装共通規範.md](00_実装共通規範.md) を参照。本書は日付入力・変換・検証固有の事項を記す。

## 基本方針

- アプリケーション内部の日付は文字列ではなく `java.time.LocalDate` で保持する。
- 画面フォームと API が受領する日付文字列は ISO 8601 の `yyyy-MM-dd` とする。
- 入力文字列から `LocalDate` への変換、値域チェック、項目間の前後関係、画面表示用の整形を分離する。

## 共通部品

- `com.system_server.ai_demo.commons.web.IsoLocalDateEditor`
  - Spring MVC のフォーム入力 `yyyy-MM-dd` を `LocalDate` に変換する。
  - 未入力（`null`・空文字）は `null` とする。
- `com.system_server.ai_demo.commons.validation.DateInBounds`／`DateInBoundsValidator`
  - `LocalDate` が 1900-01-01 以上 9999-12-31 以下であることを検証する。
- `com.system_server.ai_demo.commons.validation.DateRange`／`DateRangeValidator`
  - 注釈で指定した2項目の `LocalDate` が「自 ≤ 至」であることを検証する。

## 実装ルール

- フォーム／API の DTO の日付項目は `LocalDate` とし、サービス層で日付文字列を再解析しない。
- Spring MVC のフォームでは `@InitBinder` から `IsoLocalDateEditor` を登録する。API の JSON は ISO 形式で受け取る。
- 日付形式または実在日の不正は入力値から `LocalDate` への変換エラーとして扱う。
- 値域は `@DateInBounds`、項目間の前後関係は `@DateRange` で検証する。未入力を許容しない項目には必須制約を別途付ける。
- 画面上の `YYYY/MM/DD` 等への整形は表示境界でのみ行い、フォーム送信値や内部型に流用しない。
- 機能ごとに日付パターン、`DateTimeFormatter`、日付変換処理を重複定義しない。
