# 00_共通部品 導出判断メモ

> 本メモは生成時点の導出記録である（承認後は書き換えない。承認後の人手変更の正史は実施単位直下の `ケース変更台帳.md` が担う）。

## 位置づけ

`00_共通部品` は**横断仕様のオーナー機能**（実施単位・配置規範）である。システム共通仕様書群
（画面部品仕様・画面部品凡例・画面共通仕様・入力値チェック・API共通仕様・ユーザ認証認可・
パーマリンク・CSV共通仕様・営業情報メール）を導出元とする導出単位を本機能に一元化し、
ケースは**代表画面の操作**として設計する。各画面機能の棚卸しには画面固有の差分だけを立て、
部品・共通仕様の一般挙動は本機能のケースへ横断参照で閉じる。

一部の導出単位は、**代表となる画面機能へ委譲**する（オーナー機能から画面機能への委譲参照は
行アンカー形式 `` `<機能>` #<棚卸し行>（<ケースID>） `` で書く）。委譲する主なもの:

- 入力値チェック共通仕様の各ルール — 項目×ルールの適用は各画面の機能仕様書・モデル型定義書が
  定めるため、ルールが働くこと自体は各画面の代表ケースで受ける。
- CSVの囲み文字の適用（値にカンマ・ダブルクォーテーション・改行を含む場合） — 部署マスタの
  部署名は使用文字が全角文字に限られ、これらの文字を値に持てない。値にこれらを持てる
  案件情報一覧のCSVダウンロードを代表とする。

## 表示精度に関する注記（整合チェッカー C7 の警告について）

画面部品仕様「ファイルサイズの表示」は「四捨五入した結果の小数部が0となる場合は、小数部を
省略して整数で表示する」（表示例「1KB」）と定める。整合チェッカーの既定表示整形
（`format_size_default`）は小数第一位まで出す（`1.0KB`）ため、ケース 4-6・4-7・4-8 の
サイズ表記は **値は一致し表示精度のみ既定と異なる** 警告になる。設計の表示規則が正であり、
本文は設計どおりに記入している。
