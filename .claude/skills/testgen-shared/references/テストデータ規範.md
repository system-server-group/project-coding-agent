# テストデータ規範

- テストデータ・期待値・投入/取込ファイルに言及するときは、**実在し参照可能なファイルの相対パス**を明記する。総称・プレースホルダのみの記述は禁止。
- **シード CSV は全行に主キー（ID）を明示**し、自動採番へ依存しない。**自動採番の列（IDENTITY 等）も CSV に明示**し、シーダーが `OVERRIDING SYSTEM VALUE` で投入する。シードの ID 帯域とテスト中の UI 操作による採番帯は**境界値で分離**する（明示 ID と自動採番の衝突回避＋UI 採番 ID をシード件数に依存させない決定性のため。境界の既定値はハーネスの `E2eSeedSupport.SEED_ID_MAX`（=1000）で、プロジェクトの要求でシード帯域を変える場合は糊クラス等プロジェクト側に定義した有効値を `parseSeedId` と `moveSequencePastSeedBand` の両方へ渡し、その定義を境界の正本とする）。期待結果には具体 ID を書き、**画面上の ID 表示と証跡上で突合できる**ようにする。
- **1画面原則**: 検証対象が 1 フレームに収まるデータ量・表示件数でケースを設計する。
  - **適用除外**: ページング・スクロール・大量リストなど、1 フレームに収まらないこと自体が検証対象であるケースには 1画面原則を適用しない。これらは連続フレーム規格（証跡規範）を前提に、表示件数設定・母集団サイズを調整して到達に必要な最小のデータ量で設計する（到達手段カタログ 手段7）。
  - **1画面原則を対象外理由に用いることを禁止する**。「母集団を大きくすると 1 フレームに収まらない」はスクロール・ページング系の観点を対象外とする根拠にならない（整合チェッカーが機械検出する）。
- `ケースID ↔ 使用データファイル ↔ 期待値` が、仕様の記述だけで一意にたどれる状態にする。
