# テストケース仕様書 共通記載規範

> 本書はテストケース仕様書（テスト仕様書様式）に共通する記載規範を定める。各様式固有の規範は、本書群の各様式別の記載規範を参照。
> 様式の構成（ヘッダー・列・記法）の正本は書式凡例（`テストケース_書式凡例/雛形_テスト仕様書.xlsx`）。本書はその記入方法・解釈を補う規範であり、様式そのものを再定義しない。
> 本書の例はすべて凡例ベースの抽象例（`Sample…` 等）であり、特定機能には依存しない。

## 正本の考え方
- **様式構成**の正本：書式凡例（`テストケース_書式凡例/`）。
- **ケース内容（観点・前提・操作・期待結果）**の正本：基本設計・詳細設計、および実装（画面の実挙動）。凡例のサンプル記述は内容の正本ではない。
- **ケース識別**の正本：機能名＋No（機能内で一意。採番形式は様式別の記載規範を参照）。トレーサビリティの軸。
- **テストデータ**の正本：csv（`テストケース仕様/<実施単位>/<機能>/data/`、ベースラインは `テストケース仕様/<実施単位>/_baseline/data/`）。
- **実行証跡**：エビデンス（`テストケース仕様/<実施単位>/<機能>/エビデンス/`）。配置・形式は E2E テスト共通規約に従う。
- `<実施単位>`（例 `20260713_初回リリース`）は 1 回のテスト実施の単位。再テストは別の実施単位フォルダを起こして実施する（E2E テスト共通規約「テスト実施単位」）。

## ヘッダー枠
| 項目           | 規範                                                                               |
| -------------- | ---------------------------------------------------------------------------------- |
| システム名     | システム名（プロジェクト固定値）。                                                 |
| 機能グループ   | 対象機能の基本設計ヘッダー「機能グループ」を転記（例：共通基盤）。                 |
| 機能名         | 対象機能名（例：Sample 機能）。                                                    |
| 作成日／作成者 | 作成日＝作成時点（`YYYY-MM-DD`）。作成者＝作成者氏名。凡例・既存物からの流用禁止。 |
| 実施日／実施者 | テスト実施時に記入。新規作成時は空。                                               |

## 記載粒度
- **操作手順**は、担当者が同じ操作を再現できる粒度で、画面の操作単位に番号を振って書く。
- **期待する結果**は、**画面から実際に観測できる挙動**で書く。合否を一意に判定できること。
- 設計から導いた観点が実装の画面制約（入力属性・クライアント検証・遷移規則 等）で**到達不能**な場合は、断定せず確認の上で観点を見直す。
- 列見出し・他列が既に担う情報をセルで重複しない。

## 採番・セル構造
- **No** は手打ちの採番（機能内で一意。セクション番号＋枝番の形式は様式別の記載規範を参照）。自動採番は用いない。
- 前提条件・操作手順・期待する結果など複数段からなるセルは、**セル内改行**で段階を分けて書く。
- 結合セル（ヘッダー枠等）は起点セルへ記入する。

## 凡例の扱い
- 凡例にはサンプル値・記入例が含まれる。**内容は転記しない**（内容は設計・実装から導く）。様式の正しい構成のみ凡例を正とする。

## 秘匿情報
- 認証情報・個人情報・シークレットを本文・データ・証跡に残さない。記載するのは**開発環境専用のダミー値**のみ。
