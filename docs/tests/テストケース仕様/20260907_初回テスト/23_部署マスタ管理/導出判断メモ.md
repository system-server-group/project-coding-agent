# 23_部署マスタ管理 導出判断メモ

> 本メモは生成時点の導出記録である（承認後は書き換えない。承認後の人手変更の正史は実施単位直下の `ケース変更台帳.md` が担う）。

## 位置づけ

部署マスタ管理画面は、部署マスタの一覧表示・CSVダウンロード・CSVアップロード（洗い替え）を行う画面。
本機能は**画面固有の項目・
テーブル表示仕様・テーブル操作・CSVの列と行・ファイル形式チェック・入力値チェック（部署マスタ
レコード）・洗い替えの異常分岐**を受け持つ。

横断仕様に由来する一般挙動（ページネーション部品の各状態・CSVの様式と読み取り・
認証認可・パーマリンク）は、オーナー機能 `00_共通部品` のケースへ横断参照で閉じる。

## データ設計上の制約（部署マスタ固有）

共通レイアウトの初期表示は、ログイン中ユーザの部署IDに合致する部署マスタレコードの部署名を
必要とし、存在しない場合はエラー画面【サーバー内部エラー】へ分岐する（`01_共通レイアウト` #18）。
部署マスタ管理画面自体も共通レイアウトを使用するため、**洗い替え後の部署マスタには、
実施者であるシステム管理者 SM0002 の部署ID 3 が必ず含まれている必要がある**。
本機能の洗い替え正常系のデータ正本（`23_部署マスタ管理/data/洗い替え_正常.csv`・
`23_部署マスタ管理/data/洗い替え_境界値正常.csv`）はいずれも部署ID 3 を含む。

この制約の帰結として、**部署マスタが0件の状態を作れない**（0件＝実施者の部署も存在しない）。
0件時の表示・0件時のCSVダウンロードに関する導出単位（#35〜#39・#48）は対象外候補とし、
質問リスト Q4 で裁定を得る。

## ソートの並び順の根拠（照合方式）とソート確認用データ

設計は「対象列の値は文字列としてソートする」と定める（部署マスタ管理画面 画面レイアウト 3.7.3）。
ベースラインの部署名（営業部・開発部・管理部）は漢字であり、**文字列の照合方式によって並びが
変わる**（コードポイント順では 営業部→管理部→開発部、読み順では 営業部→開発部→管理部）。
設計は照合方式を定めていないため、この母集団では期待値が一意に定まらない。

そこでソートを確認するケース（2-3・2-4）は、コードポイント順・五十音順のどちらでも同じ並びになる
カタカナの部署名を用いた専用シード `23_部署マスタ管理/data/ソート確認_部署マスタ.csv`
（部署ID: 1「デルタ課」・2「アルファ課」・3「チャーリー課」）で実施する。部署IDの昇順とは異なる
並びになるため、ソートが適用されたことも判別できる。実施者 SM0002 の部署ID 3 を含む
（上記「データ設計上の制約」）。
