# API エラー応答の実装規範

> 共通規範は [00_実装共通規範.md](00_実装共通規範.md) を参照。本書は API のエラー応答の実装固有の事項を記す。

## 基本方針
入力チェック違反は共通ハンドラ `com.system_server.ai_demo.commons.error.ApiExceptionHandler`
（`@RestControllerAdvice`）で一括して HTTP 400 の `ErrorResponse`（`errors[]`）へ変換する。

## 規約
- 1 つの画面項目につき**メッセージは 1 件**。同一項目に複数違反がある場合は、**入力値チェック一覧でより小さい番号**の
  チェックのメッセージを採用する（「最大文字数 / 日付形式」を「使用文字 / 日付下限」より優先＝入力値チェック共通仕様の並び）。
- **`errors[]` の項目間の順序は規定しない。** 設計が規定するのは項目内のチェック実行順序のみで、項目間のメッセージ順序は
  未規定。画面は各項目名でエラーを対応付けるため配列順に依存しない。**規定に無い並びを共通ハンドラで勝手に課さない。**
- 共通ハンドラに**機能固有の値（項目名の一覧・項目順）を持たせない**。優先順位はチェック種別（システム共通）に基づく。
