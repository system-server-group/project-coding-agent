# 画面コントローラー定義書 記載規範

> 共通規範は [00_共通規範.md](00_共通規範.md) を参照。本書は本様式固有の事項のみ記す。

## 役割
ViewModel ＋ テンプレートを返すコントローラー（クラス）**1件**の定義。配下に**複数のエンドポイント**を持つ。

## 配置・ファイル名
`イベント定義書/コントローラー定義書/<機能>[_<アクション>]_画面コントローラー定義書.docx`。

## ヘッダー固有
- 機能グループ：対象機能の所属グループ（基本設計ヘッダーから転記）。
- 機能：`<機能名> / <コントローラー論理名>`（2段落）。

## 本文の構成と書き方
- **コントローラー基本情報**：論理名／物理名（`～Ctrl`）／ベースパス（`/...`、`/api` を付けない）／処理内容。
- **公開エンドポイント一覧**（エンドポイントごとに以下を繰り返す）：
  - **エンドポイント基本情報**：論理名／物理名（camelCase）／メソッド／**パス設定**（ベースパスからの相対）／処理内容。フルパス＝ベースパス＋パス設定。
  - **入力仕様**：No / 論理名 / 物理名 / 型。
  - **入力チェック（実行順）**：No(自動採番) / 論理名 / 共通チェック仕様名・個別内容。
  - **出力仕様**：
    - **テンプレート**：使用する画面テンプレートを `※画面テンプレート一覧【...】を参照` で記す。
    - **バインド変数**：No(自動採番) / 論理名 / 物理名 / 型（ViewModel の項目。サーバ側で渡す値が無ければ `―`）。
  - **処理フロー**：No(自動採番) / 概要 / 内容。

## 固有の決定事項
- **凡例の節見出し錯誤**（「入力仕様」と「入力チェック（実行順）」のラベル取り違え）が含まれることがある。成果物では正しいラベルに**補正**する。

## 記入例（抽象・処理フロー）

| ---------- | ---------------------- | ------------------------------------------------------------------------------------------------------------- |
