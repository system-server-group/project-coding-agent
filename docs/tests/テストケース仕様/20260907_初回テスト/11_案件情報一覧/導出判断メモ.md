# 11_案件情報一覧 導出判断メモ

## 位置づけ

案件情報一覧画面は、9種の検索条件による案件情報の検索・24列のグリッドテーブルによる一覧表示・
列レイアウトのローカルストレージへの保存／復元／リセット・CSVダウンロードを行う画面。
本システムで最大規模の画面機能である。

横断仕様に由来する一般挙動（部品としてのページネーション・オートコンプリート・カレンダー、
CSVの様式と読み取り、認証認可、パーマリンク、API共通仕様）は、オーナー機能 `00_共通部品` の
ケースへ横断参照で閉じ、本機能には**検索の意味・テーブルの表示仕様・列固定・レイアウトの
保存と復元・CSVの列と行**という画面固有の差分を立てる。

## CSVダウンロードの列内容についての解釈（質問リスト Q6）

機能仕様書 6.2.5 は「列に表示する内容は案件情報一覧画面 画面レイアウト#案件情報テーブルで
定義された各項目とする」と定める。案件情報テーブルの入出力仕様には「改行は半角スペースで
置換する」（案件概要・備考）・「YYYY/MM/DD形式」（開始日・終了日）・区分の表示文字列
（「オープン」「必要」「請負」等）が含まれる。

本メモはこの記述を**テーブルの入出力仕様がそのままCSVの列内容になる**と読み、期待値
`11_案件情報一覧/data/CSV期待_既定検索_管理コード降順.csv` を作成した。すなわち区分値は表示文字列、
日付は YYYY/MM/DD、日時は YYYY/MM/DD hh:mm:ss、案件概要・備考の改行は半角スペースに置換、
値の無い項目は空欄である。

この読みでよいことを**質問リスト Q6 で裁定済み**である（ユーザー裁定: 表示値と読む）。
6.2.5 が表示仕様の書かれた案件情報テーブルそのものを参照していること、および他のマスタ画面の
CSVも画面の表示値で出力する設計であることが理由である。カンマ・ダブルクォーテーションを含む値の
囲み文字とエスケープ、および空欄を囲まないことは、どちらの読みでも同じであり 6-1 が受ける。
