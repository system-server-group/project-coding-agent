# サービス定義書 記載規範

> 共通規範は [00_共通規範.md](00_共通規範.md) を参照。本書は本様式固有の事項のみ記す。

## 役割
サービスクラス**1件**の定義。配下に**複数のメソッド**を持つ。**業務ロジックの所在**となる層。

## 配置・ファイル名
`イベント定義書/サービス定義書/<論理名>_サービス定義書.docx`（`<論理名>` は基本設計の（サービス）論理名。クラス名（`～Service`）は本文・一覧表で定義する）。

## ヘッダー固有
- 機能グループ：サービスの所属グループ。
- 機能：`<サービス論理名>`（単段落）。

## 本文の構成と書き方
- **サービス基本情報**：論理名／クラス名（`～Service`）／処理内容。
- **公開メソッド一覧**（メソッドごとに以下を繰り返す）：
  - **メソッド基本情報**：論理名／物理名（camelCase）／処理内容。
  - **入力仕様**：No / 論理名 / 物理名 / 型。
  - **出力仕様**：No(自動採番) / 論理名 / 物理名 / 型。
  - **処理フロー**：No(自動採番) / 概要 / 内容。

## 固有の決定事項
- **業務ロジックをここに置く**：検索条件の組立・絞り込み規則・ドメイン変換 等を実装非依存で詳述する。
- **委譲先のデータアクセス（DB/IF）メソッドを明示する**（`【...Mapper】の<メソッド>に委譲` と記す）。「対応するデータアクセスに委譲」のような曖昧記述は不可。
- データアクセスから受け取った**永続化エンティティ型（`～Entity`）をドメイン型へ変換**する（区分のコード値→列挙型 等）。`～Entity` は `※テーブル定義書【...】を参照` で結ぶ（構造の正本はテーブル定義書）。
- 複数の参照元で再利用される取得は、**対象（マスタ等）の項目ごとにメソッドを分離**する（1つの集約メソッドにまとめない＝参照側ごとの再生産を避ける）。

## 記入例（抽象・処理フロー）
| No | 概要 | 内容 |
|---|---|---|
| (自動採番) | 条件の組立 | 入力から絞り込み条件を組み立てる（照合規則・結合・未指定時の扱いを明記）。 |
| (自動採番) | 取得 | 条件を【サンプルマッパー】の検索（search）に委譲し、永続化エンティティ（`SamplesEntity` 一覧）を取得する。 |
| (自動採番) | ドメイン変換・返却 | 永続化エンティティ（`～Entity`）をドメイン型に変換し（区分コード→列挙型）、呼び出し元に返す。 |
