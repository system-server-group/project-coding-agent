# クラス図 ― 共通基盤（認証・認可／共通レイアウト／エラー／ログイン）

論理名で表記（物理名は各定義書で確定）。レイヤ: コントローラー → サービス → Mapper(1表専用) → エンティティ。
認証・認可はフレームワーク（フォームログイン／URLベースのアクセス制御）が担うため、本図には業務クラスとして示さない（許可表・アクセス制御の遷移は画面遷移図を参照）。共通レイアウトの初期表示はユーザ参照・部署参照（マスタ管理所属の横断参照）を利用する。

```mermaid
classDiagram
    direction LR

    class ログインCtrl {
        <<controller>>
        +ログイン画面表示()
        +認証要求(ユーザID, パスワード)
    }
    class 共通レイアウトCtrl {
        <<controller>>
        +初期表示()
    }
    class エラーCtrl {
        <<controller>>
        +エラー振り分け(404/403/500)
    }
    class ユーザマスタマッパー {
        <<mapper>>
    }
    class 部署マスタマッパー {
        <<mapper>>
    }
    class ユーザマスタレコード {
        <<entity>>
    }
    class 部署マスタレコード {
        <<entity>>
    }
    class ユーザ参照Service {
        <<service>>
        +ユーザ名一覧取得()
        +ユーザ名取得()
        +部署ID取得()
    }
    class 部署参照Service {
        <<service>>
        +部署名取得()
        +部署存在判定()
        +部署名一覧取得()
    }

    共通レイアウトCtrl --> ユーザ参照Service
    共通レイアウトCtrl --> 部署参照Service
    ユーザマスタマッパー --> ユーザマスタレコード
    部署マスタマッパー --> 部署マスタレコード
    ユーザ参照Service --> ユーザマスタマッパー
    部署参照Service --> 部署マスタマッパー
```

> 補足: 認証・認可はフレームワークのフォームログイン・URLベースのアクセス制御が担い、許可表・アクセス制御の遷移は画面遷移図を参照する（本図では業務クラスのみを示す）。ユーザ参照・部署参照は機能グループ＝マスタ管理に所属する横断参照リソースだが、テーブル/DBIF のみに依存するため共通基盤からも利用される。
